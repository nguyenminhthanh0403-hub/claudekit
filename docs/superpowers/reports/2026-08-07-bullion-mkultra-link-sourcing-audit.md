# Bullion Mk Ultra — Link Sourcing Audit

Final aggregated report for the 10-task sourcing-quality audit of the causal links in `bullion-live-map/bullion_mkultra.html`. Tasks 1-9 each audited a batch of links against the 8-column verdict schema (Section, Edge, Conf tier, Citation validity, Mechanism accuracy, Currency, Suggested action, Evidence note) and staged findings to `docs/superpowers/reports/.staging/batch-1.md` through `batch-9.md`. This report regroups all 93 audited rows by their original 22 section/sub-section groups (independent of which batch covered them) and is the final deliverable of the plan.

## Note on the LINKS/PLUMBING_LINKS merge

The runtime causal graph in `bullion_mkultra.html` is not just the `LINKS` array — at load time, `PLUMBING_LINKS` supersedes 9 specific `LINKS` entries and appends the rest (see `bullion_mkultra.html:1509-1524`). This means 9 edges that still physically exist in the `LINKS` array text are dead code at runtime: the live edge a user actually sees comes from `PLUMBING_LINKS` instead, usually with a different `why`/`stat`/citation. Those 9 dead `LINKS` entries were correctly excluded from this audit (auditing them would have graded text nobody ever sees); the live `PLUMBING_LINKS` versions were audited in their place under the "(plumbing)" section labels below. This table exists so a future reader doesn't mistake the dead entries' absence from the row-by-row audit for an oversight.

|---|---|---|
| ffr→banks | 1405 | PLUMBING_LINKS:1333 |

| fed→repo | 1411 | PLUMBING_LINKS:1356 |

Note that supersession is not merely a location/text change: for `fed→repo`, the dead `LINKS:1411` entry carries `sign:-1` while its live `PLUMBING_LINKS:1356` replacement carries `sign:+1` — the live edge flips the claimed direction of the relationship, not just its wording.

The 86 `LINKS` + 16 `PLUMBING_LINKS` entries in the source file total 102 literal objects — the figure the design spec counts — but 9 of those 16 `PLUMBING_LINKS` entries supersede (overwrite) an existing `LINKS` entry rather than adding a new one, so the live runtime graph actually contains 86 + (16 − 9) = 93 edges, which is the count this audit covers; "102" and "93" are both correct, they're just counting literal objects in the source text versus live edges in the runtime graph, respectively.

## Summary

**Status as of 2026-08-08: fully resolved.** The original pass (below, historical) found 20 rows needing action (17 `update stat text`, 3 `flag for discussion` — the roll-up table originally misstated this as 5, a bookkeeping error caught and fixed during the follow-up pass). Two of those (`equit→etf`, `etf→equit`) were resolved on 2026-08-08 via live-browser primary-source verification (see their rows below). The remaining 18, plus those 2, were all resolved on 2026-08-08 in an audit-followup pass that applied each row's own evidence note directly to `bullion_mkultra.html` — see `docs/superpowers/specs/2026-08-08-bullion-mkultra-audit-followup-design.md`. All 93 rows now carry `Suggested action: none`.

- **Total rows audited:** 93 across 22 section groups.
- **Clean sections:** "Money & deposits (Mk13)" and "Mortgage rates (Mk13)" — the full set of rows drawn from pure `LINKS`-array structurally-stable relationships — came back 12/12 OK with no flags in the original pass. Geopolitics was the *least* clean section in the original pass: 4 of its 10 rows were flagged (`china→tsy`, `china→oil`, `geo→cpi`, `geo→credit`) — all since resolved.
- **Citation validity vs. Currency — the convention used throughout:** Citation validity records whether the named source is real and correctly identified (the right institution, the right paper, the right series); Currency records whether the specific figure cited is still accurate today. This distinction mattered most during the original audit pass; post-resolution, both should read `OK` for every row.
- **Recurring pattern — "real source, wrong number":** several rows cited a genuine, correctly-named primary source whose institution and mechanism checked out, but whose specific figure had drifted or was mismatched to the wrong period/paper at write time. This was the single most common finding type, and the audit-followup pass fixed all instances of it.
- **Suggested-action schema coverage (original pass):** of the schema's five declared Suggested-action values, only three appeared across the original 93 rows — `none`, `update stat text`, and `flag for discussion`. `field-note candidate` didn't appear because field-note auditing was explicitly out of scope for this pass; `reconsider confidence tier` didn't appear because `geo→credit` — the one row where a newly-surfaced dataset (the Caldara & Iacoviello GPR Index) could plausibly justify revisiting the confidence tier — was scored `flag for discussion` instead, since a tier change needed a human judgment call rather than an automated flag (that judgment call was made and resolved 2026-08-08: citation added, confidence tier left as `unverified`, since the newly-cited GPR index's finding complicates rather than supports the edge's claim).
